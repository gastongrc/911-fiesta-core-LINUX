3. SCORE AGGREGATION LOGIC
================================================================================

  Phase A: ANALYZER VOTING
  ─────────────────────────
  For each state S ∈ {bajada, base_golpe, ataque, brake}:

    raw_score[S] = count(card.is_on() == True) / count(modules_in_group)

    Module counts:
      BAJADA:     5 analyzers  → 1 vote = 0.20
      BASE_GOLPE: 10 analyzers → 1 vote = 0.10
      ATAQUE:     3 analyzers  → 1 vote = 0.33
      BRAKE:      3-4 analyzers→ 1 vote = 0.25-0.33

  Phase B: MSE BLENDING (if MSE confidence >= 0.4)
  ──────────────────────────────────────────────────
    blended_score[k] = 0.45 * raw_score[k] + 0.55 * MSE_probability[k]

    Weight split: Analyzers 45% / MSE 55%
    MSE dominates when confidence is sufficient.

  Phase C: LIGHT SMOOTHING (buffer averaging)
  ────────────────────────────────────────────
    Maintains buffer of last 2 score snapshots (FAST preset)
    smoothed[k] = avg(buffer[0][k], buffer[1][k])

  Phase D: EMA SMOOTHING
  ───────────────────────
    _scores_smooth[k] = 0.5 * smoothed[k] + 0.5 * _scores_smooth_prev[k]
    (α = 0.5 for FAST, α = 0.3 for STABLE)

  Phase E: THRESHOLD COMPARISON (priority order)
  ───────────────────────────────────────────────
    1. BRAKE   ≥ 0.65  → select BRAKE
    2. ATAQUE  ≥ 0.68  → select ATAQUE (if clean_rise or already ATAQUE)
    3. GOLPE   ≥ 0.30  → select BASE_GOLPE (if persistence ≥ 2/3 frames)
    4. BAJADA  ≥ 0.35  → select BAJADA (if clean_drop 2/3 frames)
    else: keep current state

  Phase F: VALIDATION GATES (all must pass for change)
  ─────────────────────────────────────────────────────
    - Stability window: 120ms consistency
    - ATAQUE margin: ≥ 0.12 over second score
    - Hold timer not active
    - Cooldown not active
    - Hysteresis: new_score > current_score + 0.04
    - Min confidence: ≥ 0.50


4. MSE CONTRIBUTION ANALYSIS
================================================================================

  WHAT MSE MEASURES:
  ──────────────────
  The Music Structure Engine (MSE) is an audio analysis pipeline that
  produces probabilities for each state based on real audio features:

  Sub-engine          Metric                  Range       Update Rate
  ─────────────────── ─────────────────────── ─────────── ───────────
  BeatEngine          Tempo (BPM)             70-180      Every 8 ticks
                      Beat phase              [0,1)       Every tick
                      Beat confidence         [0,1]       Every 8 ticks
  EnergyEngine        Overall RMS (EMA α=0.3) [0,1]       Every tick
                      Band energies (lo/mi/hi)[0,1]       Every tick
                      Energy trend            RISING/     Every tick
                                              FALLING/
                                              STABLE
  TransientEngine     Transient density       [0,~20/s]   Every tick
                      Transient spike         bool        Every tick
  PhraseEngine        Phrase position         [0,1)       Every tick
                      Boundary probability    [0,1]       Every tick
  DropEngine          Drop state machine      NONE/BUILD/ Every tick
                                              PRE_DROP/
                                              DROP
                      Drop confidence         [0,1]       Every tick

  HOW MSE PRODUCES PROBABILITIES (state_inference.py):
  ────────────────────────────────────────────────────

  P_bajada (raw, before normalization):
    +0.40 if energy < 0.15
    +0.20 if energy < 0.25
    +0.25 if trend FALLING
    +0.15 if trend STABLE & energy < 0.2
    +0.20 if transient_density < 3.0
    +0.15 if beat_confidence < 0.3
    Max raw: 1.0, clamped to [0,1]

  P_base (raw, before normalization):
    +0.30 if 0.08 < energy < 0.45
    +0.25 if beat_confidence > 0.3
    +0.20 if trend STABLE
    +0.15 if 3.0 < transient_density < 15.0
    +0.10 if drop_state == NONE
    Max raw: 1.0, clamped to [0,1]

  P_ataque (raw, before normalization):
    +0.25 if energy > 0.3
    +0.15 if energy > 0.5
    +0.20 if trend RISING
    +0.15 if transient_density > 10.0
    +0.15 if transient_spike True
    +0.20 if drop_state in (BUILD, PRE_DROP, DROP)
    +0.10 if beat_confidence > 0.5 & tempo > 120
    Max raw: 1.20, clamped to [0,1]

  P_brake (raw, before normalization):
    +0.30 if trend FALLING & energy > 0.15
    +0.20 if phrase_boundary > 0.5 & trend FALLING
    +0.15 if transient_density < 2.0 & energy > 0.1
    +0.10 if drop_state NONE & trend FALLING
    Max raw: 0.75, clamped to [0,1]

  NORMALIZATION: All four probabilities are divided by their sum → sum = 1.0

  CONFIDENCE: margin(winner - second) + 0.3 * beat_confidence
              Threshold for MSE effect: confidence >= 0.4

  CAN MSE DOMINATE?
  ──────────────────
  YES. MSE weight is 55% vs analyzers 45%. When MSE confidence >= 0.4,
  MSE probabilities have majority influence on the final score.

  CRITICAL: P_base has a STRUCTURAL ADVANTAGE — see section 5.


5. WHY BASE_GOLPE DOMINATES — ROOT CAUSE ANALYSIS
================================================================================

  CAUSE 1: P_base (MSE) has the WIDEST activation range
  ───────────────────────────────────────────────────────
  For typical dance/electronic music during playback:
    - energy_level ∈ [0.08, 0.45] → very common → +0.30
    - beat_confidence > 0.3       → almost always → +0.25
    - energy_trend STABLE         → most of the time → +0.20
    - transient_density ∈ (3,15)  → typical range → +0.15
    - drop_state == NONE          → >90% of time → +0.10
                                              Total: 1.00 raw

  P_base reaches its MAXIMUM (1.0) under NORMAL music conditions.
  No other state achieves maximum under normal conditions.

  After normalization, P_base = 1.0/total where total includes all states.
  Even with P_ataque = 0.65 simultaneously, P_base still wins:
    P_base_norm = 1.0 / (1.0 + 0.65 + ~0.35 + ~0.15) ≈ 0.47
    P_ataque_norm = 0.65 / 2.15 ≈ 0.30

  CAUSE 2: BASE_GOLPE has the LOWEST threshold (0.30)
  ────────────────────────────────────────────────────
  Threshold comparison for activation:
    BRAKE:      0.65 (very selective)
    ATAQUE:     0.68 (very selective)
    BASE_GOLPE: 0.30 (extremely permissive)
    BAJADA:     0.35 (permissive)

  With MSE blend: blended_golpe = 0.45 * votes + 0.55 * P_base
  If only 2/10 analyzers active (votes = 0.20) and P_base = 0.47:
    blended_golpe = 0.45 * 0.20 + 0.55 * 0.47 = 0.09 + 0.26 = 0.35
    This PASSES the 0.30 threshold.

  Even with ZERO analyzer votes:
    blended_golpe = 0.45 * 0.0 + 0.55 * 0.47 = 0.26
    This is just BELOW 0.30 but after smoothing may cross.

  CAUSE 3: BASE_GOLPE has the MOST analyzers (10)
  ─────────────────────────────────────────────────
  More analyzers = higher probability of achieving any given vote ratio.
  With 10 rhythm-detecting analyzers, even 3 being active gives 0.30.
  Rhythm detection is inherently "easy" for music with any beat.

  CAUSE 4: Persistence requirement is easily met
  ───────────────────────────────────────────────
  BASE_GOLPE persistence: 2/3 frames with _scores_smooth >= 0.52
  BUT the threshold check uses RAW scores (0.30), not smooth scores.
  Persistence check uses _golpe_persistence which tracks smooth >= 0.52.
  This creates a DISCONNECT:
    - Raw score passes threshold (0.30) → state selected
    - Smooth score may not reach 0.52 → persistence blocks
    - BUT once smooth score reaches 0.52 for 2/3 frames → locks in
    - Once locked in, BASE_GOLPE's 0.48s hold prevents leaving

  CAUSE 5: ATAQUE is structurally difficult to reach
  ───────────────────────────────────────────────────
  ATAQUE has only 3 analyzers (SnareRoll, HiRoll, BurstSharpness).
  Threshold: 0.68, meaning 3/3 analyzers must be active (2/3 = 0.67 < 0.68).
  ALL THREE must fire simultaneously, which requires a very specific
  audio pattern (snare roll + hi-hat roll + spectral burst).

  Additionally:
    - ATAQUE needs clean_rise (3 consecutive increasing scores)
    - ATAQUE needs 0.12 margin over second-place score
    - P_ataque in MSE peaks only during high energy + rising trend

  CAUSE 6: MSE P_base and P_bajada OVERLAP with P_brake
  ──────────────────────────────────────────────────────
  P_brake requires: trend FALLING + energy > 0.15
  But P_bajada also activates on FALLING trend + low energy.
  When energy falls from medium to low, BOTH P_bajada and P_brake increase,
  diluting each other. Meanwhile P_base may still be high from its STABLE
  energy condition (trend detection has latency).

  CAUSE 7: Double smoothing creates momentum
  ───────────────────────────────────────────
  Scores pass through:
    1. Light smoothing (buffer avg, size=2)
    2. EMA smoothing (α=0.5)
  This creates inertia — once BASE_GOLPE scores are high, they decay slowly.
  Combined with the 0.48s hold, BASE_GOLPE can persist through brief
  interruptions that should trigger other states.

  CAUSE 8: Priority ordering creates a "gravity well"
  ────────────────────────────────────────────────────
  The decision logic checks states in priority order:
    BRAKE → ATAQUE → BASE_GOLPE → BAJADA
  Since BRAKE and ATAQUE have HIGH thresholds (0.65, 0.68), they rarely
  activate. BASE_GOLPE with 0.30 is the first "easy" threshold to pass.
  The system falls through to BASE_GOLPE as the default "active music" state.

  SUMMARY OF ROOT CAUSES (ranked by severity):
  ─────────────────────────────────────────────
  [CRITICAL] MSE P_base structural advantage — reaches max under normal music
  [CRITICAL] BASE_GOLPE threshold (0.30) too low relative to MSE contribution
  [HIGH]     ATAQUE requires ALL 3/3 analyzers (threshold 0.68 > 2/3=0.67)
  [HIGH]     MSE weight (55%) allows P_base to single-handedly pass threshold
  [MEDIUM]   Double smoothing creates score momentum favoring current state
  [MEDIUM]   10 rhythm analyzers make BASE_GOLPE voting inherently easy
  [LOW]      Hold timers prevent quick corrections after false BASE_GOLPE entry
